# Ordinary MegaMoE: policy, compilation and execution

Only ordinary MegaMoE is changed. Each layer's shared FFN stays in the framework.
The shared-fused branch is not loaded.

1. The V4 router evaluates FP32 scores and gathers the selected logical IDs'
   differentiable scores. IDs and routing-weight semantics stay unchanged.
2. The common runtime exchanges per-source expert counts and checks collective
   metadata. A policy sees counts, capacity/slot limits and its cost model.
   It receives no model Parameter, optimizer state or ready-flag authority.
3. The policy emits `copies[EP,slots]` and `quota[source,expert,destination]`.
   Global quotas, ECHO two-pass allocation and UltraEP locality are policy
   details before that common proposal boundary.
4. The public compiler checks source marginals, unique/nonempty/fixed-home
   replicas, contributor sets and capacity. Ranks compare quota fingerprints;
   then every original assignment is mapped exactly once. The existing fused
   collective validator independently checks materialized routes.
5. The same ordinary executor consumes the plan to move weights, run forward
   and backward and return gradients to fixed owners. It never dispatches on a
   planner name. Zero-task replicas are rejected; every nonzero replica keeps
   its complete dW1/dW2 delivery obligation.

`CommonOnlinePlanner.compile_proposal()` accepts external device proposals and
uses the same collective compiler/refusal/recovery path as built-in policies.

## Existing API and device lifetime

`ExecutionPlanSpec`, `PlanningContext`, prepared/replay plans and checked leases
are retained. `planner_contract.py` is an independent NumPy test oracle, not a
second training runtime. `ExecutionPlanBody` is the immutable device snapshot:
routes, copies, counts, source quota and control template are cloned away from
planner scratch. It owns no stream, epoch, model weight or optimizer state.

`PlanTicket` separately owns an invocation's lifetime. Original forward plans
once; non-reentrant checkpoint replay rebinds that body to a fresh lease;
backward restores the live framework-owned weights and uses saved placement.
After one backward the step retires the ticket. Duplicate replay, retired
ticket and body mutation are rejected. Step/layer identity is explicitly
installed by the harness; no sitecustomize or pointer guessing chooses a plan.

generation is not part of training.

## Keeping the initial baseline binary

The baseline SO has an optional policy-module registration hook. Its five
existing policies and external-proposal compiler stay frozen. Later step_time
uses a separate module and the same frozen compiler source. Registration does
not replace the baseline SO, Host extension or ordinary compute worker. An
absent/uncalibrated module fails explicitly.

Actual loaded SOs and model SHA are recorded. Online search/compilation belongs
inside timing; replay-only timing is never an online planner score.

## Confirmed cost-model boundaries

- Early dW1 requires at most32 physical experts. The main64-slot shape follows
  the complete existing tail dW1 path; the model must use that boundary.
- After P1 dH/SwiGLU gradients, GM backward P2 interleaves each expert's dW2
  before its dX. Tail dW1 follows P2; owner service overlaps and keeps existing
  projection/tile order and waits. See ACTUAL-DEPENDENCIES.md for source anchors.
- Saved BF16 gate/up skips backward's optional GMM1 recomputation; whole-layer
  checkpoint still invokes the ordinary forward again. Home-only tiling uses32
  physical experts, but gradient.ready is disabled, also preventing early dW1.
- Existing Native feature counts explicitly say `predicts_time=False`; they
  cannot be presented as measured latency.
- The isolated original AscendTimerV2 build samples column0 gradient blocks and
  owner service, plus complete original per-expert phase timers. Sampling is a
  model limitation. Rank-local zero points are never merged into a global axis.
