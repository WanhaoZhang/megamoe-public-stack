# `step_time`：面向普通 MegaMoE 训练步的保守成本搜索

本轮实现的是可以替换规划策略的统一执行路径，以及一个待实验检验的成本策略。
它不改变逻辑 TopK、不迁移专家/优化器 owner，也不替换 MegaMoE 前反向 kernel。
模型中的 shared expert 继续由框架计算。性能结论以完整训练步数据为准。

## 实际接口与调用

`CommonOnlinePlanner` 将当前逻辑 IDs 交给公共直方图交换。策略只看到当前的
来源计数、容量/槽位限制和冻结成本，不持有 Parameter、SHMEM ready 或 stream。
输出为 `copies[8,32]` 和 `quota[8,256,8]`。公共编译器检查每个来源的任务守恒、
非空且唯一的副本、固定 home、接收容量和八 rank 计划一致性，再物化物理 IDs。
每条原始 token–expert assignment 恰好执行一次，路由权重及逻辑专家不变。

正文 `ExecutionPlanBody` 与 epoch/stream/容量租约分开。原始前向规划一次；
整层非重入 checkpoint 重放和 backward 复用正文并重新绑定租约，最后退休。
执行器没有按策略名称选择 kernel 的分支。合法的非均衡接收上限统一为163840；
原32槽二进制和64槽二进制能力在加载时核对。

独立插件 `mega_moe_step_time_planner.cpp` 由冻结公共源生成。它只扩展策略决策，
不改公共编译/物化正文，也不重建已经测量的 Host、原公共 planner 或 worker。
128KiB 的规划 workspace 与模型前缀分开；模型 JSON、实际加载 SO、决策数组
和源码身份分别记录。加载时检查实际专家矩阵形状和容量，语义成本模型必须在
显式门禁环境中启用，不能进入正式模型批准列表。

## 预测的依赖

用整数16ns单位进行 max-plus 预测；下面是依赖关系，不是把所有 Timer 区间相加。

| 部分 | 预测边界 |
|---|---|
| 前向 | 实际 AIC 先遍历全部 GMM1 再遍历 GMM2；GMM1/SwiGLU 使用192行 tile，其他行任务128；dispatch、activation、combine 和权重就绪按依赖重叠 |
| 反向 | 重算实际 GradientKey；P1 的 dH/SwiGLU 后逐专家 dW2→dX，P2 后尾部 dW1；保存 gate/up 不等于省掉整层 checkpoint 前向 |
| 梯度归主 | 奇/偶 owner worker 从实际 P1/P2 边界进入；保留 dW2→dW1、home expert 和静态 tile 顺序；候选改变最后一个副本时重新排所有受影响专家 |
| 梯度义务 | 每个非零远端副本都保留完整56MiB dW1＋28MiB dW2；只有配额变为零才能移除它的梯度贡献者；不按 token 比例缩小梯度 |
| 链路 | 当前来源 quota 决定 token 交通；权重与梯度按完整副本计算；用实测链路/fanout 和正干扰系数约束并发资源 |
| 框架 | 两层模板包含原前向、checkpoint replay、shared/routed/attention backward、三次 owner 镜像发布、FSDP、clip 与两个 AdamW；只预测当前计划对代表性整步的边际影响 |

不读取下一层或下一步的 IDs。整步模板重复当前层候选的代表成本，并非知道所有
未来路由的跨层最优调度。不能假设现有 kernel 支持免费跨层延迟梯度或任意重排。
通信资源使用每对rank流量/fanout界限，副本就绪采用均匀进度近似；它没有重放
每条RMA stripe的真实发出顺序。梯度tile的首尾释放用同一调用内的样本估计，
中间以线性进度近似。CPU事件图验证这套近似的算术和依赖实现，不等于已经
还原了NPU的真实全局关键路径。原始rank时间轴、阶段边界和预测残差分别保留。

## 校准、搜索与误差

起点在独立 seed20261114、MaxVio0.3/7/18 的15次 Timer-OFF整步运行中按几何
平均选出 Native。主银行和两个 heldout 银行均不参与拟合。

八个原始 AscendTimerV2 诊断训练覆盖五种已有策略及无副本分支；原始区间
首先按每个 rank/AIC/AIV 导出。Event 嵌套区间只扣并集，不拼接各设备零点。
GEMM/tile、路由和 owner tile 服务的正系数拟合使用步骤1/2验证步骤3，再
重拟合1/2/3。额外的0.5/1/2/4/8正干扰网格在首次独立校准出现稠密副本
反向低估后声明，仍然只使用校准数据。该扩展属于校准过程中的模型修订。

最终数据/权重复制/owner干扰系数为0.5/4/8；owner达到网格边界，说明模型
仍不充分。它们是拟合修正，不能当作实际链路带宽。完整步时差值的校准
P90误差加基线均值误差为47.40ms，作为决策裕量；首次未修正模型为215.74ms。
这些都是校准误差，不是新策略的性能收益，也不是测试集泛化保证。
路由/计算阶段的拟合包络可能带有等待与相关性，不能把回归系数解释成独立
的物理每字节耗时。单链路样本最大32MiB，完整专家平面使用线性外推和干扰
修正；奇数owner lane也没有逐tile直接样本。这些局限参与最终结论解释。

搜索考虑返回副本到 home、128行负载移动（保留末尾残块）、只调整来源 quota
的局部性、迁移副本执行地点。上限4轮/每轮64个候选，独立设备开销实测后
采用1轮/最多4个候选，覆盖四类操作；各类固定顺序及 tie-break。每个候选
重算非零贡献者、释放时间和 owner 服务。越出已测任务行数/活跃专家范围则拒绝
使用该候选；起点越界时保留起点并记录状态。

采用条件是预测整步节省严格超过模型误差和两层规划增量。增量按
`evaluations + 2*rounds + 1` 收费。未达到门槛就精确恢复起点的副本顺序和来源
quota；搜索耗时仍算进正式训练步。非法计划、OOM 或超时不会被伪装成该回退。

## 验证与判读

可移植 C++ 策略与独立 Python 逐任务依赖图交叉核对，公共 NumPy 编译器
独立验证 assignment 身份和守恒。设备门禁再比较完整 copies/quota/physical IDs
及决策字段，覆盖非法配额、重放和恢复；数值门禁比较输出、dx、路由权重、
routed/shared 梯度；两层门禁污染缓存并反序反向。正式模型还需通过三次 Adam
更新、全局梯度缩放一次、实际 FP32 持久状态和 BF16 计算镜像检查。

`evidence/step-time-qualification.json` 是最终通过凭据；没有此凭据不能进入
正式矩阵。`analysis/planner-decisions-summary.json` 统计实际正式执行的采用、
误差回退和起点越界次数，不能用隔离重放代替实际采用记录。

主矩阵之后还需第四轮和两份独立银行。只有每点4/4同向且改善中位数至少1%
才达到预定稳定门槛；只有稳定点存在才运行三项消融。即使门槛通过，也要检查
实际计划是否改变，不能把起点计划或运行噪声的收益归因于梯度服务模型。

MegaFlux已考虑 tile 与反向归并，PlaceMoE已考虑布局/映射和梯度重叠，TopoEP/
TAOT已考虑拓扑。本轮不能据此宣称新的算法贡献；已有工作边界和固定源码见
[研究边界](../references/RESEARCH-BOUNDARIES.md)及[策略移植说明](../references/POLICY-PORTS.md)。
