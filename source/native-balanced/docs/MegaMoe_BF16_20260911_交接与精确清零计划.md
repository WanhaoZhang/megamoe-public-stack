普通 BF16 控制区总范围仍为：
`72 KiB + EP * AlignUp(EP * expertsPerRank,128) * 4`。
Host 每次实际清零从72 KiB开始，仅包含公式中的 token 表。EP8/EPR4清4 KiB，
EP512/EPR4清4 MiB；总控制区分别为76 KiB和4,268,032 bytes。
本地穷举5366组 EP/专家数组合检查无越过 payload；这不是设备验证。

当前正确性依赖以下顺序：Host 在当前 stream 清本 rank 的 token 表 -> 同 stream 启动
Kernel -> Kernel 入口 `CrossRankSyncInWorldSize()` 确认所有 rank 的本地清零已完成 ->
执行路由/计算 -> Kernel 退出前的 Device barrier 发布安全复用边界。launcher 不再执行
每次调用的 `aclrtSynchronizeStream/aclshmem_barrier_all`。不要删除入口/出口 Device barrier，
也不要把 Host 的同 stream 顺序误当成跨 rank 可见性。

当前分支在 PR16 和 `154f90a` 基础上的处理：
- 每次只清完整 token-per-expert 表，payload 和72 KiB同步头部均不清。
- 删除 `ASCEND_DEEPEP_SKIP_WINDOW_MEMSET` 诊断开关，每次 raw/train 前向均执行。
- 两个入口复用同一个清理 helper，并增加清理范围不超过窗口容量的 Host 检查。
- 修正语义说明：计数发送是 counts+0x800000 覆盖写、接收再减标记；本地
  InitRouting histogram 才是原子累加，因此 token 表在入口必须为零。
- 创建普通 BF16 SHMEM 实例时保留一次 Host barrier；每次前后向使用 Device 入口/出口
  barrier。前向和反向 Kernel 尾部的 ResetTokenPerExpert 仍保留。

### 6.1 PR29 Device barrier 的功能边界

PR29（`154f90a`）不改变前后向数学计算、Tensor 形状或公开返回值，但改变了同步发生的
位置以及 Host 能观察到的行为，后续接入必须遵守以下约束：

- 普通 BF16 的 SHMEM 对象构造阶段会执行一次 `aclshmem_barrier_all()`，保证所有 rank
  完成同步头部的首次清零后再使用 generation counter。因此所有参与 rank 必须以一致
  顺序创建该对象；只有部分 rank 构造时会在构造阶段等待。
- 每次普通 BF16 前向或反向都属于跨 rank 集体调用。所有 rank 必须按相同顺序、相同
  次数进入；某个 rank 跳过一次调用时，会在 Kernel 内的 Device barrier 等待。
- 同一对称 SHMEM window 仍按串行生命周期使用，不能让两个 stream 并发执行共享该
  window 的前向/反向。退出 Device barrier 只发布本轮的安全复用边界，不提供多调用并发。
- Host 的 `aclrtMemsetAsync` 与 Kernel 启动依赖同一 stream 的先后顺序；其他 stream 上
  产生的输入（特别是 FSDP/HCCL 通信 stream 上的 `grad_y`）必须由框架或显式 event 建立
  到当前计算 stream 的依赖。Device barrier 只同步 rank 间的 SHMEM 协议，不能替代本 rank
  不同 stream 之间缺失的依赖。
- launcher 删除了 Kernel 后的 `aclrtSynchronizeStream()`，所以调用更异步；Kernel 异常
  可能在后续 `torch.npu.synchronize()`、Event 等待或其他同步 API 才上报。定位错误时要保留
  首个设备错误和随后发生的同步位置，不能把延迟报错位置直接当作故障阶段。
- 72 KiB 同步头部保存跨调用递增的 generation counter，不能恢复成每次入口清零；每次
  只清 token-per-expert 表。普通 BF16 Host、前向 Kernel 和反向 Kernel 必须使用同一套
  头部偏移与协议，并同时重新编译，不能混用新旧二进制。
- 本改动只覆盖普通 BF16 前后向。UDMA、MGroup 仍使用各自的同步和布局，不能照搬这套
  generation counter 结论。

现有普通 BF16 `run_precision.sh`/`run_speed.sh` 可以验证常规 current-stream 路径，但不能
单独证明真实 FSDP/HCCL 多 stream 接入正确。正式训练接入至少要增加连续多步、通信与计算
stream 重叠条件下的精度和无卡死验证。

### 7.1 Host 改为 empty 后的 Kernel 完整定义契约

这里不是把 Host 的全量清零简单移动到 Kernel。Host 使用 `torch::empty/empty_like`
以后，分配器返回的每一个字节都可能带有旧数据；正确性完全依赖 Kernel 在任何消费者
读取或 Tensor 返回给框架之前，完整定义实际可见范围：

- `gradX`：P2 必须覆盖 `[M,K]` 的全部逻辑行，不能只覆盖非空专家对应的 packed 行。
- `gradTopkWeights`：P6 必须覆盖 `[M,TopK]` 的每条 route，包括尾块；不能依赖未写位置
  原本为0。
- `gradWeight1/2`：每个本地专家的完整物理 plane 必须且只能由下面两条路径之一写完：
  - `effectiveRows > 0`：P3/P4 DW GEMM 覆盖完整 plane；AIV 不清该专家。
  - `effectiveRows == 0`：P3/P4 不启动该专家的 DW；所有 AIV 分片清完整 plane。
- `effectiveRows` 的计算必须继续与 `UpdateGroupParams()` 的有效行和 `maxOutputSize`
  容量裁剪语义一致。路由行数非0、但已落在容量边界之外的专家，同样属于空专家，
  必须清零梯度。

因此，后续如果修改专家遍历顺序、groupList 类型、容量裁剪、DW 跳过条件、权重物理布局
或 `transW` 处理，必须同时审查 `ClearEmptyExpertGradWeights()`。一旦两边对“空专家”的
判断不一致，会出现两类问题：两边都不写导致旧显存泄漏为梯度，或者 AIC DW 与 AIV 清零
同时写同一 plane 形成竞争。

### 7.2 AIV 清零流水的硬性要求

- 每个 AIV 负责的 GM 区间必须互不重叠并覆盖完整 plane；起点和分块保持32字节对齐，
  尾块不能漏写。不能退化成单核清几百 MiB。
- 16 KiB 零块位于固定 staging UB。只有 P0/P2 已经排空、该窗口不再被前序阶段使用后
  才能复用；后续若移动 P5 或改变 UB 复用时序，必须重新证明生命周期不重叠。
- 第一次搬运前保持 `MTE3_V -> Duplicate -> V_MTE3` 依赖；所有 UB 到 GM 的 DataCopy
  完成后，保持 `MTE3_S` 等待，再进入本地/跨 rank barrier 或复用 staging UB。
- 不得在 P5 晚期重新使用 `InitGlobalMemory`。该接口要求发生在 Kernel 中所有
  `InitBuffer` 之前；违反顺序已在设备上触发507015。晚期清零继续使用已经生成的 UB
  零块和 MTE3 DataCopy，或者重新设计成满足接口时序的入口阶段方案。
- 没有空专家时不得生成零块或发起清零搬运；这样常见均衡路径只承担空专家判断，
  不承担权重 plane 写流量。

### 7.3 后续修改的最小回归范围

任何触碰上述 Host 分配、DW 调度、空专家判断、UB 布局或事件依赖的修改，至少验证：

1. 全部专家非空：确认 AIV 不覆盖 DW 结果，四项梯度精度通过。
2. 自然空专家和容量裁剪产生的空专家：确认对应 `gradWeight1/2` 整个 plane 为0，
   并覆盖首、中、末专家。
3. 非整 tile 的 M/专家行数、连续多轮 forward/backward，以及当前支持的两种权重布局。
4. 普通构建跑精度和正式性能；Timer 构建只用于归因，不能作为最终性能结果。
5. 同时重新编译 Host 扩展和 BF16 Kernel，不能只替换其中一个二进制。

本轮设备证据只覆盖普通 BF16 8卡；大 EP、UDMA、MGroup 仍不能据此标记为通过。

### 7.4 PR29 与 PR30 叠加后的同步契约

- PR29 的跨 rank Device barrier 负责调用边界和 SHMEM 可见性；它不负责把 PR30 的
  `torch::empty/empty_like` 输出初始化为零，也不能替代输出路径的完整覆盖。
- PR30 的非空专家 DW 与空专家清零写不同的 expert plane。两边对 `effectiveRows` 的判断
  必须保持一致，才能保证同一 plane 恰好由一条路径完整写入，避免漏写或并发覆盖。
- 空专家的 UB 到 GM 清零必须先通过 `MTE3_S` 排空，随后才能进入本地及跨 rank barrier。
  不能因为 PR29 已有退出 Device barrier 就删除这条本核 MTE3 完成依赖。
- 前向 `y/expertTokenNums` 与反向四项梯度在 Kernel 成功完成后才是完整定义的数据；同
  stream 消费遵循流顺序，Host 立即读取或跨 stream 消费仍须具备相应同步依赖。
- 两项修改叠加后没有改变公开 ABI、返回 Tensor 的形状、数值公式或训练保存状态布局。
  当前8卡精度结果支持常规路径，但不自动覆盖真实 FSDP 多 stream、大 EP、UDMA 或 MGroup。

## 8. 后续排队，不能一起开工

1. SHMEM 首次精确初始化或省掉复用清理：需用途、shape、生命周期和跨 rank 协议证明，非本轮范围。

## 9. 接手工作方式

- 第一轮先复述：当前基线、PR16框架配套纠正、下一项范围、禁止顺带修改内容。
- 每次只完成一阶段；结论标明源码确认、推断、CPU检查、用户设备反馈。
- 遇到证据不足，定位到具体字段/函数继续读；不能用“通常覆盖写”替代证明。
- 每个完成阶段在本文补充状态、commit、检查与待验证项，保持交接入口简短准确。
- 给设备命令必须可复制，结果输出到屏幕；不要求用户发送 bin/json。
- 不重启 UDMA 调试，不接管别人的反向算法，不新增额外模型/agent并行任务。
