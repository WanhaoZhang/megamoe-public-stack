# 共享专家与内核 X 重派发：使用和复现

本指南对应共享前向、共享反向V2和内核X/prob重派发V3。目标分支原有的共享反向ABI1保留；普通路由接口和默认saved模式保留。本次17项算子验收及完整F/B结果见[验收报告](内核X重派发八卡验证结果-20261101.md)，真实FSDP整网尚未验收。

## 模式怎么选

`shared_save_mode=keep|recompute`只控制共享专家限幅前的BF16 G/U和BF16激活A：keep保存引用，recompute在反向重算；两者都保存原X引用，不额外clone原X。

| benchmark `--routed-input-mode` | 外置对照链路 | 融合链路 | 生产桥设置 |
|---|---|---|---|
| saved（默认） | 外置共享，保存packed X | 共享融合，保存packed X，V2 | `routed_input_mode='saved'` |
| redispatch | 外置共享＋外置X重建 | 共享融合＋外置X重建 | 仅benchmark的外置适配器 |
| native | 外置共享＋外置X重建 | 共享融合＋内核X/prob重建，V3 | `routed_input_mode='redispatch'` |

```python
y = bridge.forward_shared(
    x, ids, prob, shared_gate, shared_up, shared_down,
    limit=10.0, shared_save_mode='keep',
    routed_input_mode='redispatch',  # 显式V3；省略时仍是saved/V2
)
```

仅调用新API不会自动使用V3或本次逐tile配置。桥每次通过live权重回调获取参数，不缓存前向unsharded指针供反向使用。保存态及ABI见[接口说明](../integration/wuhan/SHARED-EXPERT-FORWARD-ABI.md)。

## 开关与兼容性

| 设置 | 本次取值 | 作用 |
|---|---|---|
| `MEGAFLUX_SHARED_EXPERT_FORWARD` | 1 | 构建共享前向 |
| `MEGAFLUX_SHARED_EXPERT_BACKWARD` | 1 | 构建共享反向ABI1/2/3 |
| `MEGAFLUX_SWIGLU_DECOUPLE` | on | 构建时显式GM解耦 |
| `MEGAFLUX_GM_SWIGLU_TILE_READY` | 1 | 构建逐tile ready流水 |
| `MEGAFLUX_SHARED_EXPERT_TILE_PIPELINE` | 1 | 运行时启用共享逐tile前向 |
| `MEGAFLUX_BACKWARD_RESTORE` | 2 | S9 panel restore |
| `MEGAFLUX_RESTORE_PANEL_ACQUIRE_CACHE` | 0 | 本次未开启该候选 |

S9旧默认构建的auto实际保持0（UB），显式on为1（GM）；新增shared-forward或GM-tile前向opt-in允许auto为2。共享反向单独开启不改变旧auto选择，普通BF16 target不受此S9规则影响。CMake缓存`MEGAFLUX_EFFECTIVE_SWIGLU_DECOUPLE_MODE`记录实际值；请求模式与实际值分别写入构建记录。本次H7168复现须显式on，不能用auto替代。

## 前置条件

本次环境为950、完整CANN 9.2.0 B237、driver SPC105B200、Torch 2.10.0、torch_npu 2.10.0.post6及匹配的SHMEM。先在自己的独立容器确认8卡空闲。SHMEM Python模块和Host链接库必须来自同一安装；bootstrap会拒绝加载两套SHMEM。

初始化子模块、source匹配的CANN，然后在独立环境执行`bash scripts/build.sh -soc_type Ascend950`，构建基础SDK/kernel/Host。Host必须包含新的共享及V3接口，不能只换worker SO。

外置共享参考使用MindSpeed-LLM提交`111aa86a2deb2f5697ae7ed1eed8e9532ce6ce8d`的`mindspeed_llm/fsdp2/ops/triton_swiglu_with_limit.py`，SHA为`b2d6ff717fec5c184fa31cf53796a5fab2aca9036c185c5b278d5da91ea3ced7`。不要误用另一份`ops/triton`同名文件。

```bash
export ROOT="$PWD"
export SHMEM_HOME_PATH="$ROOT/3rdparty/shmem/install"
export MINDSPEED_ROOT=/path/to/MindSpeed-LLM_wuhan
export TRITON_REFERENCE="$MINDSPEED_ROOT/mindspeed_llm/fsdp2/ops/triton_swiglu_with_limit.py"
git submodule update --init --recursive
bash scripts/build.sh -soc_type Ascend950
command -v npu-smi
npu-smi info
sha256sum "$TRITON_REFERENCE"
python3 - <<'PY'
import importlib.util, pathlib, runpy
root = pathlib.Path(importlib.util.find_spec('triton').origin).parent
detector = runpy.run_path(str(root/'tools/get_ascend_devices.py'))
assert detector['is_compile_on_910_95'], '950 detection failed; inspect real CLI/driver'
PY
```

容器须有本机真实`npu-smi`。本次缺CLI且PCI条件为false时，Triton误选A2/A3编译函数，arch字符串仍显示950；仅设置arch变量不能修复设备检测。不得伪造CLI输出。

## 当前shape最小复现

用户入口只有`benchmark_shared_expert_fb.py`；`benchmark_shared_expert_forward.py`是其输入、统计及Timer解析依赖。输出目录必须全新，master和SHMEM端口须确认空闲。

```bash
export PYTHONPATH="$ROOT:$ROOT/test/megamoe_planner_test:${PYTHONPATH:-}"
export TORCH_DEVICE_BACKEND_AUTOLOAD=0 PYTHONDONTWRITEBYTECODE=1 PYTHONNOUSERSITE=1
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 TASK_QUEUE_ENABLE=2
export WUHAN_PUBLISH_SYNC=device WUHAN_CONTROL_TAPE_DEVICE=npu WUHAN_POOL_AUDIT=0
export MEGAFLUX_SHARED_EXPERT_TILE_PIPELINE=1
unset ASCEND_LAUNCH_BLOCKING WUHAN_REPLAY_CAPTURE_DIR ASCEND_CUSTOM_OPP_PATH
export MEGAMOE_RESULTS="$ROOT/results-$MEGAFLUX_VARIANT"

run_fb() {
  local variant="$1" output="$2" master_port="$3" shmem_port="$4"; shift 4
  local native="$ROOT/worker-variants/$variant"
  local torch_lib npu_lib
  torch_lib=$(python3 -c 'import importlib.util,pathlib;print(pathlib.Path(importlib.util.find_spec("torch").origin).parent/"lib")')
  npu_lib=$(python3 -c 'import importlib.util,pathlib;print(pathlib.Path(importlib.util.find_spec("torch_npu").origin).parent/"lib")')
  WORKER_NATIVE="$native" LD_LIBRARY_PATH="$native:$torch_lib:$npu_lib:$ROOT/ascend_deepep/lib:$SHMEM_HOME_PATH/shmem/lib:${LD_LIBRARY_PATH:-}" \
  torchrun --nnodes=1 --nproc-per-node=8 --master-port="$master_port" \
    integration/wuhan/runtime_bootstrap.py --native-only integration/wuhan/benchmark_shared_expert_fb.py \
    --out "$output" --world-size 8 --ep 4 --tokens 8192 --hidden 7168 --ffn 3072 \
    --experts 8 --topk 2 --slots 2 --capacity 20480 --route rank_skew --rho 6 --hot-experts 2 \
    --seed 42 --limit 10 --repeat 3 --routed-input-mode native --shmem-port "$shmem_port" \
    --triton-reference-file "$TRITON_REFERENCE" "$@"
}

run_fb "$MEGAFLUX_VARIANT-off" "$MEGAMOE_RESULTS/keep-off" 28480 28490 \
  --timer 0 --shared-save-mode keep --warmup 10 --measure 30
run_fb "$MEGAFLUX_VARIANT-off" "$MEGAMOE_RESULTS/recompute-off" 28500 28510 \

run_fb "$MEGAFLUX_VARIANT-on" "$MEGAMOE_RESULTS/keep-on" 28520 28530 \

  --timer 1 --shared-save-mode recompute --warmup 0 --measure 0 \
  --reference "$MEGAMOE_RESULTS/recompute-off" --clock-probe-so "$CLOCK_PROBE_BUILD_DIR/libdeepep_clock_probe.so"

python3 integration/wuhan/export_shared_fb_trace.py --input "$MEGAMOE_RESULTS/keep-on" --out "$MEGAMOE_RESULTS/keep-traces" --world-size 8
```

NoTimer流程包含精度和首次有效X/prob前缀核验；正式计时关闭审计哈希及Timer，按AB/BA交替、逐迭代取8rank最大值。Timer须引用同输入/配置的OFF结果并逐位核对；导出完全离线，默认隐藏wait。

## 实现与内存契约

- 前向共享Gate/Up与双AIV初始化重叠，逐tile SwiGLU/Down与Dispatch配合；共享输出按既有BF16边界在Unpermute合入。
- V3复用冻结排列、计数和偏移；共享GU/dA期间准备X/dY/prob，五个共享梯度GEMM期间由AIV0 Dispatch dY、AIV1搬X/prob并恢复权重。
- X源暂借`ptrD`，全EP读取退休及`VECTOR_RETIRED`后才允许覆盖；不重新planner/sort/count all-gather。ABI1/2/3分别为152/184/200字节。
- native前向tape不保存packed X，反向仍有临时重建区。本次Torch分配器峰值高176.03MiB，SHMEM另计；释放tape不等于整卡峰值降低。
- Host先清零完整物理槽计数，解决home-only仅写home项时尾槽垃圾值被误计为额外行的问题。

## 框架交接边界

当前FSDPTurbo/MindSpeed的`shared_expert_mode=fused`只接共享V2，未传`routed_input_mode`，仍为saved：反向读取前向packed X。它不等于独立benchmark已验的native/V3；旧外置redispatch环境开关也不能替代V3配置。

配套PR需在MindSpeed参数→FSDPTurbo配置→dispatcher→桥之间透传策略，缺省保持saved，显式redispatch启用V3。还须核实绕过共享MLP的`__call__`后，真实FSDP hooks仍能在前反向准备好共享参数。

kernel返回direct dX（含共享贡献）、dP、路由dW1/dW2及共享dWg/dWu/dWd。dP→router dX留给框架；共享梯度归普通FSDP，路由梯度归Expert-FSDP/owner SUM。真实unshard、梯度归约、动态权重、多step、checkpoint/UAM及整网step尚待框架验证。

合入顺序：算子PR→两个框架配套PR→根仓固定合入SHA。完整机器排查和历史实验留仓外；本指南仅保留当前入口和必要契约。
