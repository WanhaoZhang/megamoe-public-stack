## 摘要

MoE 系统可以通过复制热点专家，在设备之间重新分配工作；也可以把不同微批次、不同层的就绪任务组合起来，利用负载互补。但对带有反向、重计算、梯度归并和优化器屏障的训练，选择更均衡的任务组合，不必然缩短完整训练更新。我们研究一个具体问题：**如何联合决定本次执行哪些就绪任务、怎样组合，以及哪些热点专家值得复制，使同一批数据的一次 optimizer 更新尽早完成？**

我们提出一个待验证方案：在真实执行器支持的动作中，对任务集合和副本配额联合搜索，用包含梯度释放、owner 服务、权重准备及资源依赖的成本模型比较完整更新的剩余时间。其核心假设是：**任务组合会改变副本的边际收益，副本规划也会改变任务之间的互补性，因此二者不能总是独立决定。**

目前在 Ascend 八卡完成了作者核心 MaxUtil 规则的训练适配。在目标 MaxVio10 的三个时间相关性场景中，单轮筛查分别比固定同层分组慢 0.62%、0.34%、1.53%。这些结果说明当前实现没有证明动态选择优势；它们尚不能证明具体慢因，更不能作为新联合策略有效的证据。

## 1. 问题：均衡的任务组合，为何未必是更快的训练更新？

### 1.1 研究目标和不变量

给定同一次 optimizer 更新的数据、当前就绪任务、逻辑专家路由、固定参数及 optimizer owner、共同内存预算，规划器决定：

1. 当前执行哪些任务，哪些任务有界推迟；
2. 同层或跨层任务是否组合，采用什么实际执行模式；
3. 哪些设备执行哪些专家的工作，是否启用副本及其来源感知配额。

目标指标为：

$$T_{\mathrm{update}}=\max_r\left(t^{(r)}_{\mathrm{device\ complete}}-t^{(r)}_{\mathrm{update\ start}}\right).$$

它覆盖全部 GA4 微批次、在线观察和规划、前反向、重计算、梯度归并、全局 norm、clip 和 Adam。逻辑路由权重、每份 token–expert assignment、有效标签归一化、参数版本及更新次数不变。不读取尚未产生的路由，不跨更新使用旧权重。

### 1.2 时间互补的收益有明确前提

以两个设备为例，任务 A 的计算负载为 `(8,2)`，任务 B 为 `(2,8)`。忽略其他成本，分别执行的计算时间为 `8+8=16`，组合执行为 `max(8+2,2+8)=10`。这是理想负载示例，数字没有时间单位，不是训练实测。

EasyBalance 利用这种互补性，在固定专家映射下选择跨层就绪微批次。其原场景是推理；负载向量合并的不等式不能直接证明带有额外执行开销的完整训练步永不变慢。[EasyBalance §4](https://arxiv.org/html/2608.07964v1)

在你的训练执行器中，组合还可能改变：

- **权重准备和 kernel 形状。** 两个不同层需要两套专家权重；同层组合不需要扩展逻辑专家域。活跃专家数、tile 尾块和分波边界也会不同。
- **反向就绪和梯度交付。** 合组输出共享实际执行节点与缓冲租约，不能任意拆成独立反向；是否推迟了某个梯度，需要从真实依赖验证。
- **副本义务。** 非零配额副本产生实际完整权重梯度贡献，不能因为只处理少量 token，就按 token 比例忽略这份交付。
- **保存态和框架成本。** checkpoint、FSDP 驻留、池复用及在线选择自身都消耗资源。HBM 低于门槛不等于这些操作免费。

真正应比较的是不同动作造成的**完成时间差**。原始通信量、梯度矩阵大小或所有 kernel 时长的总和，都不能替代这个差值。

### 1.3 强空间基线进一步改变了问题

本项目旧诊断中，Native 空间规划后的平均实际执行 rank MaxVio 已约为 0.014；输入的固定 home rank MaxVio 约为 0.362。说明原始 home 负载很不均衡，不代表强空间基线之后仍有同等均衡空间。[诊断依据](diagnostics/actual-plan-balance.json)

这只是一个诊断点、一个简化负载指标，**不是 1.4% 的硬件加速上限**。它提示新的收益可能来自减少不值得的复制或避免执行依赖，而不是继续降低已经很小的 assignment 偏斜。

## 2. 相关工作及本问题与它们的关系

“为什么已有方法不够”应理解为它们的决策变量和执行假设不直接覆盖本问题，不能写成它们普遍无效。

| 工作 | 已经解决的事情 | 本研究仍需处理的选择 |
|---|---|---|
| [MoonEP](https://github.com/MoonshotAI/MoonEP/blob/master/README.md) | 根据当前路由动态启用冗余专家，使每 rank 执行量固定为 S×K，并处理权重预取与梯度归主 | 不以选择跨层就绪任务组作为主要决策变量；完全等量也未必是包含额外状态成本后的最快动作 |
| [UltraEP §4–5](https://arxiv.org/html/2606.04101v3) | 逐微批次、逐层规划 quota 与来源感知 reroute，并联合设计通信流水 | 其单次 MoE 规划不等价于联合选择本次应执行的多个训练任务；不能说它没有考虑规划和通信开销 |
| [EasyBalance §4](https://arxiv.org/html/2608.07964v1) | 在固定映射下，从不同层的就绪微批次中选择互补工作，降低推理空闲 | 训练梯度交付、重计算和更新屏障会改变组合的实际代价；单纯 MaxUtil 并不编码这些依赖 |
| [MegaFlux §3、附录 A.2](https://arxiv.org/html/2610.00671v1) | tile 级副本分配与持久核流水；反向规划已用 owner 副本归并罚项 | 其固定罚项 λ=12 不显式建模梯度释放时间或重叠；本文候选要验证“相同副本在不同任务组中价值不同”，不是首次考虑梯度 |
| [PlaceMoE §III](https://arxiv.org/html/2610.14798v1) | 联合优化专家布局与来源感知 token-to-copy 映射，考虑分层去重通信和计算，并重叠副本梯度同步 | 其显式优化变量是布局和映射，不包括当前跨微批次就绪集合的选择；不能把“联合优化布局/配额或考虑梯度”再当新贡献 |
| [Afore §5–6](https://arxiv.org/html/2610.03203v1) | AFD 推理中，利用真实微批次需求和可重叠窗口，仅在净收益为正时迁移，并复用已有副本 | 有暴露迁移成本和副本复用的直接先例；训练还需处理副本梯度及更新依赖，不能把缓存或净收益判定本身包装为创新 |
| [Lancet](https://arxiv.org/html/2404.19429v1)、[Tessera §3.2](https://www.usenix.org/system/files/osdi26-hu-weifang.pdf) | 整图计算通信重叠、任务移动；Tessera 已有 deadline、内存约束和可移动 Wgrad 池 | 整图、deadline、就绪队列都不是新的。候选区别必须是任务分组与复制产生的依赖变化如何共同影响决策 |

与 PlaceMoE 最需要明确区分：其目标式基于路由 profile 比较通信和计算代价，并采用梯度同步重叠；本方案拟把**在线任务组选择**加入变量，并保持训练 owner 固定。这个变量差异仍不足以自动构成创新，必须证明简单组合已有方法确实遗漏了有价值的选择。

本次重点复核上述论文的方法、目标式及相关实现边界，没有声称全文精读整个资料库，也不据此确认会议录用或专利新颖性。

## 3. 拟议方法：由更新关键路径共同决定分组和复制

### 3.1 核心假设

设 G 为一组当前就绪任务，R、Q 分别为副本位置和来源配额。副本的边际价值应定义为：

$$\Delta_{\mathrm{copy}}(G)=\widehat T_{\mathrm{remaining}}(G,R_0,Q_0)-\widehat T_{\mathrm{remaining}}(G,R_1,Q_1).$$

这里比较的是同一组任务下，增加副本前后的完整更新剩余时间，而不是只比较 token 偏斜。

如果组合已填满原来空闲的设备，复制可能减少不了多少计算，却仍增加权重准备和梯度义务；如果热点相同，复制可能仍有价值；如果某个副本的梯度交付恰好落在更新尾部，同样的复制动作可能比落在已有重叠窗口中更昂贵。

这三个“可能”均是**待验证机制**。现有结果尚不能证明发生了哪一种。

### 3.2 输入状态与合法动作

状态包含已完成依赖的任务及其真实路由、当前参数版本、权重准备状态、池租约、剩余内存，以及由独立校准得到的执行成本。没有真实权重缓存时，不将其标记成可用资源；未来路由以未知处理。

当前首版只搜索下列实际支持的动作：

| 动作 | 真实执行边界 |
|---|---|
| 单任务 Native | 32 home＋最多 32 replica 槽，完整 16K FFN 调用 |
| 同层合组 Native 或固定 home | 逻辑 home 仍为 32；保留现有 kernel 行数上限、分波和屏障 |
| 跨层固定 home 合组 | 两层占满 64 home，当前没有额外复制槽；两个完整 16K 任务需分为两个波次 |
| 选定任务分别执行 Native | 保留各自空间规划，遵守串行池；不假设大核自动并行 |
| 有界推迟 | 允许其他就绪工作前进，不在没有合法进展时空等，不读取未来路由 |

64 槽及 16K 单波行数是**当前执行器约束**，不是 MoonEP 理论要求，也不是论文希望宣称的普遍机制。若负结果完全由这些可修复的实现限制解释，应先修执行器，并将修复开放给基线。

### 3.3 公共计划及正确性约束

在已有 `ExecutionPlanSpec`、`PlanningContext` 上扩展窗口选择，继续使用统一公共编译与校验。对每个任务 j、来源 s、逻辑专家 e、执行 rank r，整数 quota 满足：

$$\sum_r q_{j,s,e,r}=n_{j,s,e},\quad q_{j,s,e,r}\geq0.$$

只有持有该任务对应 `(layer,expert,parameter_version)` 的有效 home/副本才允许正配额。梯度贡献者从真实非零配额推导，零任务副本不等待。物理路由守恒，原始 token–expert assignment 恰好执行一次，逻辑 expert 身份与 router 分数不变。

原始前向只提交一次不可变计划，checkpoint 重放和反向绑定同一正文；租约可重新绑定，不能重新做策略决策。各 rank 的执行及 collective 次序一致。全部梯度完成以后执行一次 norm、clip 和 Adam。预算核算包括跨层同时存活的权重、激活、接收区和梯度暂存，而不只是复制槽数。

### 3.4 成本模型：预测依赖图的结束时间

根据实际运行时建立候选动作的事件依赖图 D(a)。节点包括在线规划、权重准备、MoE 前向、重计算、反向、梯度分块就绪、owner 服务完成及最终消费；Attention/FSDP/shared expert 和更新操作也保留在依赖中。只采用现有 kernel 真实暴露的同步和资源边界，不虚构免费 Wgrad 拆分或跨层梯度延迟。

加入实测资源串行边和并发争用代价后，事件完成时间递推为：

$$\widehat F_v=\widehat d_v+\max_{u\in\mathrm{pred}_{D(a)}(v)}\widehat F_u.$$

终点为完整 optimizer 更新的设备完成。允许重叠的计算和通信不重复相加；不同 rank 使用因果事件建立约束，不拼接独立零点时钟。

模型特别区分：

- GEMM 的任务行数、活跃专家数、tile 尾块和 32/64 home 域，而非只有总 token；
- 副本权重真正何时可读，而非只看通信字节；
- 副本 dW1/dW2 分块何时产生、owner 何时接收完成、下一消费者何时等待；
- 每个非零配额副本的完整梯度义务，而非将矩阵字节数按 quota 比例缩小；
- 共同池的真实复用和重计算依赖；
- 在线统计、编译、校验和搜索开销。

若某个 owner 服务路径经验证确为串行队列，才使用 `完成=max(本块就绪,上一块完成)+本块服务时间`。不能先假设所有梯度串行，再用该假设证明归并是瓶颈。

决策为：

$$a^*=\arg\min_{a\in\mathcal A_{\mathrm{legal}}(s)}\left[\widehat T_{\mathrm{remaining}}(s,a)+\widehat T_{\mathrm{decision}}(a)\right].$$

`remaining` 的终点定义在提交动作以后，因此决策开销单独加入，不能既放在图中又加一次。对尚未产生的工作，只能使用历史估计和既知依赖骨架，并记录不确定性，不能使用实验银行中未来的 IDs。

### 3.5 有界搜索和保守选择

当前 W2 只有少量任务子集，先枚举合法任务组和模式。各模式调用现有空间策略产生初始配额，再进行小规模确定性修改；每个候选重新计算真实贡献者与资源依赖。CPU 参考用于检查语义；正式在线路径需采用设备实现或经计时验收的在线实现，不能用离线计划重放成绩替代。

每次决策包括固定同层分组和独立 Native 等强基线动作。只在预测收益超过搜索代价和校准误差时改变动作；阈值由独立校准集确定，在正式测试前冻结。没有足够证据时沿用基线，并计入整个决策成本。

动作集合包含基线，仅说明理想准确模型拥有更大选择空间，**不保证真实运行不退化**。模型误差、额外在线开销或执行器限制都可能使它更慢。

## 4. “为什么我们可能可以”：必须检验的机制

候选策略的根据是它能比较 MaxUtil 或逐调用复制未直接比较的联合动作，而不是“多考虑几个因素就一定更快”。应证明以下三项：

1. **动作排序反转。** 在同一真实执行器下，更高利用率的合法组，或复制后更均衡的计划，实际完整更新反而更慢；反转能由具体等待链解释。
2. **副本价值随分组变化。** 保持专家身份、数据和更新语义不变，在组 G1 中有利的同一类复制，在 G2 中无利或有害；差异不是隐藏的 checkpoint、代码版本或预算变化。
3. **依赖模型能预测并利用反转。** 在未调参路由上，它能选对动作，并在计入在线成本后胜过固定分组、FIFO、简单 EasyBalance＋复制和合理的副本复用基线。

如果只有第 1 项而没有第 2、3 项，得到的是性能分析，还没有形成有说服力的新 planner。若复制次数或 tile 数的简单模型就能解释所有决策，复杂关键路径模型也不构成必要贡献。

本方案不预设梯度一定是主因。下一步必须测到完整就绪—服务结束—消费者等待链；若证据指向共同执行层的开销，就先优化共同执行层。

## 5. 已有效果：训练适配已完成，新策略尚无成绩

### 5.1 共同实验条件

Ascend 950DT×8，普通 MegaMoE；V4 attention/mHC2，shared expert 由框架计算。L4、EP8/E256/Top8、H4096、routed/shared F1024；每条完整 16K 序列，microbatch1、GA4、在途窗口 W2。全局每次更新 32 条序列、524288 个有效 next-token 标签。

FP32 参数/梯度/Adam、BF16 专家计算，公开 FSDP 前向驻留，无 CPU offload；共同接收容量 262144，整卡采样峰值门槛 90GiB。输入为合法合成 token，seed42；受控银行目标 MaxVio10，实际 expert MaxVio=9.982666。

每点一个新进程，25 次 optimizer 更新，前 5 次预热、后 20 次测量；每步取八 rank 最大完整 wall。每点只有一次独立运行，20 步不是 20 次独立重复。

| 连续微批次热点相同 | 4.1861 | 4.2120 | 慢 0.62% |

### 5.3 能得出和不能得出的结论

- **已证实：** 普通分支可以正确执行多个完整序列微批次及跨层 FFN 组合；当前单轮 MaxUtil 适配未胜匹配固定分组。
- **尚未证实：** 变慢是否由专家域、反向就绪、归并、保存态或在线选择中哪一项主导；是否存在具有泛化价值的联合调度机会。
- **没有的结果：** 新联合策略的加速、Afore 真实设备缓存基线、六档正式重复、独立银行或自然路由训练结果。

因此摘要中目前只能报告这些适配和负结果，不能写“提出新算法并实现 X% 加速”。

## 6. 后续评估：怎样把候选想法变成可信论文

### 6.1 先建立因果证据

先用原始 `AscendTimerV2` 进行少量受控诊断，正常成绩仍关闭 Timer/profiler：

1. 固定同一执行清单，检查观察/选择自身成本。
2. 共同 prefix 路径下比较复制开启/关闭，区分动作收益与执行路径变化。
3. 对当前 32/64 home 域与分波建立数学正确的匹配控制，不以无效 shape 比时间。
4. 补齐梯度就绪、owner 服务结束、FSDP/clip 消费等待，并检查权重准备、保存态租约。
5. 如果只得到 kernel 排行榜或跨 rank 无因果对齐的包络，不进入“已证明关键路径”的结论。

通用前缀复用、权重缓存和执行器优化必须同时开放给适用的基线。若固定分组/FIFO 已取得全部收益，不继续将其包装为动态 planner 创新。

### 6.2 建立强基线

同一个普通 MegaMoE 执行器、同一参数所有权、同一 checkpoint/驻留和预算下，至少保留：独立 Native、固定同层分组、ready-FIFO、训练版 MaxUtil 固定 home、MaxUtil＋逐调用复制、以及具有真实权重版本和物理槽管理的 Afore 风格副本复用适配。

当前 Afore 只有 CPU 语义参考，不能列成已完成在线性能基线。PlaceMoE 可借鉴/适配的布局映射策略与单次 planner 比较属于受限策略对照，不冒称复现其完整多节点系统。

### 6.3 收益成立以后才扩展矩阵

先在机制筛查中对最强共同基线取得完整更新中位至少 3%、三轮同向的信号；这是继续研究门槛，不是论文录用保证。

冻结策略以后，再比较新方法与最强基线：六档 MaxVio × 三种时间相关性 × 三个独立重复 × 两种方法，共 108 次正式运行；每次 5 预热＋20 测量更新，轮换执行顺序。补独立银行、自然路由，以及不同窗口和形状的迁移验证。W4 当前未验收，不能作为已可用配置。

消融需要分别去掉任务选择、梯度释放/服务模型、副本成本和 kernel 非线性；同时加入固定梯度罚项、tile-only 预测控制，检查是否存在更简单而同样有效的解释。两个策略若选择完全相同的动作，应报告这一事实，不用很小的计时波动宣称调度优势。

报告完整更新时间、吞吐、独立运行差异和置信区间、采样 HBM、在线开销、实际副本与任务组，以及失败/OOM/超时。不同预热步或不同执行路径的数据不混算。

## 7. 预期适用范围、限制与停止条件

| 实际条件 | 候选策略应倾向的动作 | 需要验证的风险 |
|---|---|---|
| 就绪负载互补，组合新增代价低 | 固定 home 或少副本组合 | 固定分组/FIFO 可能已经足够 |
| 热点持续相同，复制成本低 | 独立或同层 Native 复制 | 不能因追求跨层而放弃强空间基线 |
| 副本计算收益小，交付恰好暴露 | 允许适度不均衡，收回不值得的副本 | 必须测到真实交付义务及等待链 |
| 组合推迟反向或增加关键资源占用 | 拆组或优先推进关键任务 | 不能只由高 MaxUtil 判定合组 |
| 没有明显可利用差异 | 维持强基线 | 搜索和观察开销仍需计入 |

这些是待检验行为预测，没有预设全 MaxVio 都加速。当前单机孤立链路差异很小，尚无可利用拓扑异质性的证据，不把“拓扑感知”强行写成贡献。未来多节点验证需另行建立环境。

只靠当前 64 槽限制、额外同步或某个框架适配缺陷产生的优势，不能证明一般性的调度价值。若共同执行优化解释全部收益、简单组合达到同样效果，或联合模型不能在独立数据上改善完整更新，应报告负结果并结束这一算法主张。

最终可以竞争论文贡献的，是：**发现可重复且超出实现偶然性的分组—复制冲突，给出能预测它的训练依赖模型，并证明在线联合选择在共同运行时下优于强基线。** 这三项目前均未完成闭环。
